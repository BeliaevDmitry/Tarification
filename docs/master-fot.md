# Сверка с Мастер ФОТ

Вкладка **Нагрузка → Мастер ФОТ** сравнивает полную выгрузку «Тарификация» с данными выбранного учебного года. Эталоном служит система. Учебный план, назначения и сертификаты система при сверке не изменяет.

## Работа с выгрузками

1. Выберите учебный год и загрузите Excel из Мастер ФОТ. Поддержан сгруппированный по педагогам лист «Тарификация»: учебная группа, часть УП, предмет, часы всего / назначено / не назначено. Заголовок содержит год и дату «Состояние на», в конце — общий итог. Несовпадение итогов или неверный год отклоняют загрузку целиком.
2. В строках сопоставления свяжите отличающиеся названия с предметами, педагогами, классами и подгруппами системы. Неоднозначные классы разных корпусов автоматически не объединяются. Составная группа с «+» сопоставляется с одной метагруппой; часы не размножаются между классами. Если записи действительно нет в системе, выберите «Отсутствует в системе» — она будет лишней записью Мастер ФОТ, а не проигнорированной строкой.
3. После сопоставления повторно загрузите тот же файл. Сопоставления сохраняются для учебного года. Есть фильтры по типу, корпусу, статусу, поиск по ФИО / классу / предмету и история итераций.
4. Отмечайте «Так и должно быть» с комментарием для намеренных отличий. Решение сохраняется при неизменных значениях. Изменившееся расхождение снова открывается.
5. После правки Мастер ФОТ можно отметить «Исправлено — ждёт проверки». Следующая полная выгрузка архивирует исчезнувшие отличия; сохранившиеся вновь открываются. Повторное появление архивной нестыковки открывает её с прежним комментарием. Кнопка «Обновить список» перечитывает сохранённые результаты, но не создаёт новую сверку.

Пока остаются несопоставленные исходные строки, сверка помечается неполной и автоматическое архивирование приостановлено. Несколько строк одной группы и предмета (например, при распределении между педагогами) складываются. Дата новой выгрузки не может быть раньше последней принятой. Каждая принятая загрузка хранит разобранные строки и результаты на тот момент. История не пересчитывается задним числом.

## Правила сравнения

- Отдельно сравниваются часы учебного плана, деление на подгруппы и назначения педагогам. Коэффициент оплаты подгруппы не используется как число подгрупп.
- Часы без назначения в системе сопоставляются с «Не назначено», а не с вакансией.
- МЦКО проверяется **на дату файла**, по существующим связям предметов МЦКО и диапазонам классов в кадровом справочнике. Используются действующие правила допуска системы: высокий / экспертный уровень; диагностика ОГЭ не заменяет МЦКО. Последний день срока действия включён. Предупреждение об истечении срока в ближайшие месяцы само по себе не требует вакансии.
- Если действующего допуска нет, вместо педагога в Мастер ФОТ ожидается вакансия по тому же предмету, части плана, классу / метагруппе и подгруппе, на полное число соответствующих часов. Имена вакансий объединяются только внутри этой позиции. Корректная вакансия показывается как «Так и должно быть». Реальное назначение учителя в системе сохраняется для работы через замены.
- Даты назначений и периоды учебного плана учитываются на дату файла. Модули сопоставляются отдельно. ИУП, финансовые суммы, контингент и коэффициенты оплаты этим форматом не сверяются.

## Права и обновление сервера

Новое право `LOAD_MASTER_FOT` находится в настройках пользователей в группе «Нагрузка»: просмотр, редактирование решений / сопоставлений и импорт. По умолчанию вкладка доступна администратору; другим пользователям права выдаются явно. Права на обычную нагрузку не предоставляют доступ к сверке автоматически. Выданное право относится к сверке школы целиком.

Сервер нужно обновить новой сборкой и перезапустить. Загрузка с номером другой школы отклоняется до создания итерации. При стандартной настройке проекта `ddl-auto=update` создаются независимые таблицы `master_fot_batch`, `master_fot_issue`, `master_fot_mapping`. Перед обновлением используйте обычную резервную копию базы. Не отключайте эти таблицы от регулярного резервного копирования: там хранятся итерации, решения и сопоставления.

## Проверки

Java-тесты: `Fot*Test`, `AuthFilterMasterFotTest`, `MckoServiceImplTest`, `AppUserServiceImplTest`.
Проверку исходной выгрузки можно включить параметром `-Dmaster.fot.sample=<путь к файлу>`; файл не копируется в репозиторий.
Браузерный сценарий: `src/test/js/master-fot-ui.cjs` (Node, Playwright на `NODE_PATH`, установленный Edge). Используются только вымышленные ответы API; снимки интерфейса сохраняются в `target/master-fot-ui`.
